# 工具注册所有权与状态

[English](2026-10-30-tool-registration-ownership-design.md) | 中文

## 摘要

本设计为工具注册和 MCP Client 实例增加只读运行时清单。清单在 Cordis 提供身份时标明所属插件，报告生命周期状态，并省略配置值和可执行回调。现有注册、冲突、作用域和清理行为继续作为最终规则。

## 问题

Harness 已经会拒绝同一注册作用域内的重复工具名，会在 MCP 实例生命周期内保留唯一的 `serverName`，并通过 Cordis effect 清理注册。这些机制可以阻止多类冲突，但调用方无法查询统一的工具所有者视图，也无法查询 MCP 连接的实时状态。

第一阶段为后续管理界面提供这类视图，不改变注册冲突的裁决方式，也不改变冲突是否会阻止插件激活。

## 设计

`dsh-tools` 通过现有的 `ctx.tools` 服务公开活动工具注册的不可变快照。每条记录包含工具名、可选的 Cordis 插件身份、注册是全局还是作用域内，以及是否声明了条件激活回调。该 API 返回注册记录，不返回某个作用域最终可见的工具列表；现有 `get()`、`definitions()` 和 `schemas()` 语义保持不变。

`dsh-mcp-client` 单独公开活动 MCP Client 实例的只读清单。每条记录包含 `serverName`、可选的 Cordis 插件身份、连接生命周期状态，以及当前已注册的公开工具名。连接 supervisor 负责状态变化，并在连接启动、重连、失败或卸载时更新清单。MCP 清单记录与 Client 实例使用相同的 Cordis effect 生命周期。

两个清单都是核心包 API。后续管理插件可以读取它们来展示诊断信息，但冲突执行和注册清理仍由底层服务负责。

## 数据与生命周期

工具快照只包含当前活动的注册。若 Cordis Loader entry 可用，则从注册它的 Cordis fiber 获取所有者；没有 Loader entry 的程序化注册明确返回无所有者，不推测身份。作用域只报告为 `global` 或 `scoped`，不暴露不透明的作用域 key 或 Agent 标识。条件激活字段表示注册声明了条件，不表示它已通过某个具体步骤的条件判断。

MCP 快照使用 `starting`、`connected`、`reconnecting`、`failed` 和 `stopped` 状态。只有连接和初始工具同步都成功后，服务器才进入 `connected`。断开后如已安排重试，则进入 `reconnecting`；重试耗尽或不再重试的失败进入 `failed`。卸载会在所属工具和传输工作清理完成后移除记录。清单不包含命令参数、环境变量、端点 URL、请求头或服务器指令。

快照方法返回分离且不可变的值。每次同步注册表变更或连接状态转换后，都能读取到最新结果。现有 disposer 仍是移除注册的唯一方式；清单 API 不提供其他修改入口。

## 兼容性与隐私

此项新增保持向后兼容：现有注册调用、重复名称错误、作用域覆盖、MCP 命名空间检查和 HMR 清理行为都保持不变。现有调用方无需读取新 API。快照不包含插件配置、秘密、工具定义、执行函数或不透明的作用域 ID。

Cordis 无法识别所有者时，API 会明确表示身份缺失。API 不读取调用栈，也不根据工具名推测所有者。API 只报告当前运行状态，不跨重载保存历史。

## 验证

测试覆盖全局和作用域内的工具所有权、所有者缺失、不可变快照、重复注册拦截、条件注册元数据、MCP 状态转换、`serverName` 唯一性，以及卸载和 HMR 后的记录清理。包文档说明快照字段和隐私限制。现有工具和 MCP 生命周期测试保持原样，只有需要覆盖新只读视图的断言才会更新。

## 范围之外

本阶段不包含管理界面、插件启停控制、自动冲突修复、配置来源追踪、持久化冲突历史、覆盖所有 Harness 服务的通用注册表，也不新增配置优先级规则。
