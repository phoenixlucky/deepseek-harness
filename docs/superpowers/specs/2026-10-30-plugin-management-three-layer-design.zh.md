# 三层插件管理与健康诊断

[English](2026-10-30-plugin-management-three-layer-design.md) | 中文

## 摘要

本设计将只读的 WJ 注册清单 bundle 扩展为覆盖 Harness Core、Management API 和 Management Plugin 的插件健康与管理界面。实现复用 Host 已有的 Loader、profile 解析器、生命周期、依赖、配置表单和插件管理能力，并补充来源追踪、冲突诊断与按风险控制的修复。

<a id="problem"></a>
## 问题

独立的 `dsh-plugin-manager-wj` bundle 当前只能读取工具和 MCP 注册快照。它不能启停插件、解释有效配置来自哪一层、查询可操作的冲突，也不能引导安全修复。

Harness 已拥有插件注册、profile 组合、包解析、插件生命周期、配置表单和插件启停能力。实现应补齐诊断与修复路径，同时避免创建第二份注册表或第二个配置写入方。

<a id="existing-capabilities"></a>
## 现有能力

Cordis Loader 管理运行时插件条目和生命周期。`app-boot` 负责解析并组合 profile 各层配置，以及兼容性预检。`plugin-manager` 读取和修改插件与 bundle 启用状态、报告受保护目标和操作结果，并安装或移除 bundle。`settings` 提供基于 schema 的配置表单和带修订检查的写入。官方 Web Plugins 页面已经能管理 bundle 及其条目。

新增功能扩展这些现有所有者，并保留 `dsh-plugin-manager-wj` 作为独立的 Management Plugin。该 bundle 聚焦于状态、诊断、配置来源、schema 表单和安全修复；不重复实现 bundle 安装或包移除。

<a id="architecture"></a>
## 架构

### 第一层：Harness Core

Cordis Loader 继续作为注册和生命周期的权威。在解析 bundle、profile、home 和 invocation 配置层时，`app-boot` 记录来源信息。来源信息标记配置层、条目和字段路径，也记录被覆盖的定义；Loader 消费的有效配置保持不变。

Host 侧诊断提供方从 Loader、profile 解析、兼容性预检、插件管理以及可用的工具/MCP 注册表中读取权威状态，并生成健康诊断。它报告有证据支持的激活失败、兼容性或依赖问题、注册冲突和配置覆盖；不会根据名称推测冲突，也不会把缺失证据当作健康。

诊断使用稳定代码、严重性、受影响的插件身份、证据引用和可用的类型化修复选项。提供方不保存第二份插件状态。本阶段可查询当前诊断和进程内生命周期事件，不增加持久化冲突历史。

### 第二层：Management API

现有 `pluginManager` Remote 继续作为标准管理命名空间。它在已有列表和启停操作之外，提供健康快照、冲突查询、配置来源查询、修复预览和修复执行。诊断规则留在 Host 侧提供方；Remote 将请求转发给该提供方和现有写入所有者。

修复请求指定一个诊断和一个类型化操作。Host 返回预览，其中包含目标、预期状态、风险级别、可逆性和影响摘要。执行时重新读取诊断和目标、检查预览修订号，并调用现有的 profile 安全操作。Host 拒绝过期、受保护、含糊或不支持的目标，不接受来自 Client 的任意文件路径、YAML 片段或插件代码。

### 第三层：Management Plugin

独立的 WJ bundle 在现有“设置 → 插件”区域扩展为健康管理面板。它调用清单和管理 Remote，并使用现有配置表单服务。页面按插件状态、健康诊断、配置来源和修复操作分组，不替换官方 Plugins 面板。

页面提供插件启停控件（Host 标记为可写时）、基于 schema 的配置表单及来源标记、冲突详情、健康摘要和修复预览。Host 状态变化后页面会刷新，并展示 Host 实际保存和应用的结果。

<a id="management-api"></a>
## 管理 API

插件状态与启停继续使用 `listPlugins()` 和 `setPluginEnabled()`。健康快照包含当前插件和 bundle 状态以及类型化诊断。冲突查询返回当前证据和进程内事件，不另存一份持久化日志。来源查询返回 schema 已知配置字段的有效来源和被覆盖来源。

来源信息标记配置层、稳定条目标识和字段路径，不返回 Host 绝对路径、原始配置文档或秘密值。配置写入仍只通过 schema 表单进行，并保留现有校验、修订冲突处理和用户层语义。

修复预览是针对某条诊断修订的不可变短期说明。只有 Host 规则将操作归类为确定、可逆、属于当前 profile 且目标安全时，低风险操作才可免确认执行。高风险和未分类操作必须在预览后明确确认。Host 在执行时重新检查资格，因此确认不能授权不同的操作或目标。

首批低风险白名单仅限可写、可选、非基础设施插件的启停，且操作必须能消除已诊断的冲突，并且不修改依赖或秘密。安装、移除、包更新、版本豁免、凭据编辑、核心服务变更、任意配置替换以及影响未知的操作都必须确认，或暂不支持自动修复。

<a id="management-plugin"></a>
## 管理插件

总览按状态和严重性显示数量，不给出含义不透明的健康分数。插件条目显示启用状态、运行阶段、所有者和 Host 是否允许修改。受保护或无法寻址的条目保留在列表中，并显示原因，不提供可操作的开关。

冲突详情展示受影响条目、证据、涉及的配置层、当前有效来源，以及可用的类型化修复。配置编辑使用已有 schema 表单。每个字段可以显示胜出的来源和被覆盖来源，同时隐藏秘密原文。修订冲突会保留表单草稿并提示刷新。

修复操作在执行前显示目标、影响、风险和可逆性。白名单内的低风险修复可以直接执行并回报结果。高风险或未分类修复需要确认。界面会区分已保存和已应用的变更，并显示重启要求或更高优先级覆盖原因。

<a id="safety-and-privacy"></a>
## 安全与隐私

Host 是强制执行边界。禁用 Client 控件仅影响显示；Host 必须独立拒绝受保护、过期或未授权的操作。每项写入都通过现有管理器或 schema 表单变更路径，保留 profile patch 语义和修订检查。

诊断 API 只返回解释问题所需的证据。它省略凭据、秘密值、可执行回调、原始插件配置、Host 绝对路径以及不透明的 scope 或 Agent 标识。来源元数据缺失时报告未知，不进行猜测。

<a id="failure-behavior"></a>
## 失败处理

不支持新诊断能力的 Host 继续显示现有注册清单，并将诊断标记为不可用；它不会把空结果显示成健康。Remote 失败会保留最近一次成功的快照并提供重试。过期的修复预览会被拒绝并要求重新生成。

配置修订冲突会保留用户草稿。profile 变更失败或部分应用时，结果会说明配置是否已保存、运行时组合是否已改变，以及重启或覆盖原因。如果 Host 保留了已保存的 profile 变更，界面不会声称已经回滚。

<a id="validation"></a>
## 验证

核心覆盖需检查跨优先级层的来源、秘密信息隐藏、冲突证据、受保护目标、风险分类、过期预览拒绝和操作结果。API 覆盖需检查 Remote 契约以及变更后的当前状态刷新。独立 bundle 覆盖健康状态、加载中、旧 Host、搜索、schema 表单编辑、冲突详情、修复确认和失败恢复。

组合 Web profile 必须展示从真实 Loader 状态经过 Host API 到独立 bundle 的完整流程，其中包含一次可写修复和一次被拒绝的受保护目标。插件注册、配置优先级、生命周期和 bundle 管理的现有行为仍由各自包负责验证。

<a id="out-of-scope"></a>
## 范围之外

本阶段不新增插件市场、安装器、更新器、移除器、任意 YAML/JSON 编辑器、通用文件系统修复接口、凭据编辑器或持久化审计日志。它不改变配置优先级、兼容性策略或现有 bundle 管理界面。Agent preset 组合保持只读，除非后续设计为其提供明确的 profile 安全写入契约。
